# 每日短信巡检工具（patrol24）

段枝宏定了早晚两次巡检（约 2026-10-10）：David 纽约时间 9 点，曾翔宇 21 点，在群里发文字，格式：

> 最近24小时内 1. 短信请求总量 2. 短信请求pass量 3. 非美国区号且非中国区号的 短信pass量 4. 区号在（21 个区号）范围内的短信pass量

这里的工具只在能连风控库的环境（MySQL 环境）里跑，桌面没有数据库连接。桌面上只做离线测试。

## 什么时候查：生产库取数时段

- 数据库语句只在纽约时间 22:00–05:30 发出（第四次取数时 M1 记下的团队规定：生产库批量统计取数只在 22:00–06:00；05:30 留余量）。
- 用户 2026-10-10 决定：21 点那次在 22:00 以后查、约 22:05 发；统计窗口不变，仍是到 21:00 为止的 24 小时。
- 工具在发语句的地方检查时间（`nightly` / `run`、子进程每条语句前、`gate`）；`emit` 只写文件，不连库，任何时间都能跑。

## 口径（定下来就不随手改）

| 项 | 定义 | 说明 |
|---|---|---|
| ① 短信请求总量 | `scene_id='LKUS_push'` 里的短信请求：`$.para.email` 为空、没有这个键、是 JSON null，或者请求 JSON 读不出 | 与第四个包的 L1 同一写法；L1 与 Doris `l2_scene='1001'` 按 UTC 日对过：9/13–10/8 共 26 天 PASS 每天相同、总量 22 天相同、4 天各差 1（包内 DR-036(a)） |
| ② 短信请求pass量 | ① 里 `result='PASS'` 的请求数 | `result` 是最终返回给调用方的结果；H5 上引擎判 REVIEW、最终返回 PASS 的也算在这里 |
| ③ 非美国区号且非中国区号的短信pass量 | ② 里区号是 1～4 位数字、且不是 1 和 86 的 | 区号为空、格式不对的不算进 ③，单独列在附加行；+852、+853、+886 算在 ③ 里；+1 包括加拿大等同区号的号码 |
| ④ 21 个区号的短信pass量 | ② 里区号在 `codes_21.txt` 里的 | 21 个区号照抄段枝宏的格式，与共用区号规则 `rule_CrVrUuDk1hHJ` 的现值相同（strategy_eoHQ6Qs0FRqp 等引用它） |

- **窗口**：截止时间 T = 当天纽约时间 21:00（`--at 09:00` 就是 9 点那次），转成 UTC 写死；起点 = T 往前整 24 小时。夏令时那天也是整 24 小时（2026-11-01 起点显示成 10/31 22:00）。
- **区号写法**：库里区号带 '+'，比较时去掉 '+'；不带 '+' 的条数单独计数，作为检查项。
- **默认截止时间**：不带 `--date` 时取"已经过了 2 分钟的最近一次截止时间"，所以 22:05 跑取的是当天 21:00，过了午夜补跑取的还是前一晚 21:00。离今天的截止时间还有 12 小时以内（比如 19:00）跑，会提示还没到时间。

## 白天测试（用户 2026-10-10 决定）

- **离线回放，任何时间：** `PYTHONDONTWRITEBYTECODE=1 python3 RC_patrol/toolkit/patrol24.py replay-test`。不连库：在临时目录里把保存过的某个 21:00 窗口（默认 10/9 21:00，早上设置会话的回复）重走一遍 emit → collect，先核对基准（要 `match`），再出群消息格式（要「可以发」），然后删掉临时目录，`RC_patrol/` 里什么都不变。
- **实时测试，只限 2026-10-10：** `run` / `nightly` / `emit` 加 `--outside-window-ok`，只限一个到 21:00 为止的窗口（slot，或只有一天的 validate_slot），语句可以在 22:00–05:30 以外发出；在时段以外用到时记进 `config/outside_window_log.csv`（写文件的命令一行，子进程发完再一行：条数、首末两条的纽约时间）。别的日期、多个窗口、别的截止时间（如 `--at 09:00`）、别的种类（backfill、纽约日、UTC 日、首次找分表）和 `eohq24.py` 一律不接受。白天直接跑 `nightly` 会被时段挡住（提示里有「生产库取数时段」，退出码 2）；加了开关的 `nightly` 在 21:02 以前提示「还没到时间」。白天要真查用 `run --validate-slot 2026-10-09:2026-10-09 --outside-window-ok`（8 条，对基准），或 `run --date 2026-10-09 --per-code --outside-window-ok`（12 条，出群消息格式；写 `posts/巡检_20261009_2100.txt`，用同样的数重写 10/9 那行历史）。今晚的续跑会话不用这个开关。

## 核对怎么防错

- **语句身份**：每条回复带窗口起止和分表范围，和 manifest 对不上就停。
- **分表**：每条回复带"有数据的分表数"和"分表编号之和"。少了分表（正常每个分表每天几十条短信请求）就停；编号对不上也停。
- **重复读**：`dup_rows` = 行数 − 按（id, 时间, 区号）去重后的行数，必须是 0。
- **时间**：回复里最早、最晚一行的时间必须落在窗口里。
- **数字**：总量 = 邮件行 + 短信行；短信 = PASS + REJECT + REVIEW + 其他结果；pass = +1 + +86 + 空 + 无效 + ③；③ = ④ + 21 个以外；0 ≤ ④ ≤ ③ ≤ ② ≤ ①。
- **按区号的四条（`w01_c*`）**：加起来必须等于 ③、④、空、无效。缺一条或对不上都停。
- 任何一项不过，退出码 4，不出群消息，也不写历史。

- 2026-10-10 设置会话看到另一个容器里的 M1 反复新建 `.db_lock`，本容器看不到持锁进程：现在 30 分钟内新建的锁一律当作「在跑」（退出码 3，提示里写「maybe another container」）。
