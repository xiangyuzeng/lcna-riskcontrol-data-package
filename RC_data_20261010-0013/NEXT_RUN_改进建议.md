## 1. 启动与权限

1. **把「网关地址从哪来」写死成一条，不要每轮在计划里问。** 本轮 Part 1 第 11 点要求「`MCP_DB_GATEWAY_SSE` 没设就别找地址、改用 MCP 逐条发」，但本机从未设过这个变量；逐条发意味着没有行级抽取（E1），DR-030 重试、窗口级去重、过滤条件重算都做不了。用户在计划评审时改为「从本机 MCP 配置读入子进程」（`RUN_LOG.md` 第一行）。建议：§1 Step A.5 直接写「未设置时从本机 MCP 配置读入子进程环境，不打印不落盘」，或者在桌面的启动步骤里先 `export` 好变量。
2. **生产库取数时段写进 §3.3。** 团队 2026-10-08 起规定批量取数只在纽约时间 22:00–06:00。本包执行器每条语句前检查，05:30 后不再发送（`toolkit/README.md`）。建议在 §3.3 加一条，并在 Step C 的「Cost」里要求列出数据库阶段能否在 05:30 前结束、不能时如何续跑。
3. **数据窗口的「运行日」按第一条数据查询的纽约日算。** 本轮包在纽约 00:13 开始，正好覆盖到 10-09；若在 22:00–24:00 之间开始，最后一个完整纽约日就少一天。建议写明：在 22:00–24:00 开跑时，先做不依赖当天的步骤，过了午夜再查当天数据。

## 3. 取数方法

8. **一次 E1、一次长聚合（L1）作为标准做法写进 §4。** 本轮 E1（≈1,700 条小时语句）服务了 P3 与 8 个 DR，L1（≈1,050 条日语句）同时回答了 DR-010 / 032 / 033 / 036；比分别取数少两三千条语句（`results/timing.csv`）。
9. **E1 的列清单固定加三类**：所有在线 / 预上线策略的规则结果（`ruleDetail`，用来重建「条件是否成立」）、每个累计特征的返回码与值、这些特征用到的维度与条件字段（含 `phoneNo` 的加盐哈希、`realIp` C 段的加盐哈希、`$.para.countryCode`）。这样过滤条件重算与 DR-030 类问题不用再抽一次（`sql/e1.sql`）。
10. **JSON `null` 要先 `NULLIF(..., 'null')` 再哈希**；行级去重用 `(shard, id)`（`05_取数手册与常见坑.md` 第 22、24 条）。
11. **执行器每次调用约 15 s 连接开销**：长抽取按天或按 7 天一次调用，写进 §4「Measure first」。
12. **跑大抽取之前做一次只读的预检复核**（代理只读新写的 SQL，不连库）：本轮在 E1 之前发现并改掉了一组问题（缺 `JSON_VALID` 保护、JSON null 被哈希成同一身份、缺 `phoneNo` 与 C 段的哈希、IP 前缀进了本机文件、L1 去重手机号按结果拆分后不能相加等），都在取数前修好（`RUN_LOG.md`）。
