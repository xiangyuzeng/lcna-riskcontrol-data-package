# 06 评估指标计算手册

> 2026-09-25 编写。每个指标给出：定义、用哪个模板（`toolkit/`）、怎么算、本包的示例数字。
> 通用约定：LKUS_push 短信口径（`$.para.email` 为空）；纽约自然日；本国区号 = `+1`（参数 `home_ccs`，可换）。

## 1. 调用量与用户量（tk01）

- **调用量**：窗口内请求次数，按最终结果（PASS/REJECT/REVIEW）与区号组拆分。
- **用户量**：窗口内去重手机号（`sharding_key`）。**只能用 tk01 输出里 `level=window` 的行**：同一窗口内各分片可以相加，但不能跨分组、跨窗口相加（见 05 §5 第 4 条）。uid 维度的用户量无法用 SQL 精确得到（uid 跨分片），需要行级抽取在本地去重。
- **示例（2026-09-24）**：LKUS_push 请求 3,225 次（短信 3,211）；短信去重手机号 1,845；+1 放行手机号 962（`results/toolkit_tests/tk01_merged.csv`，与 `results/p3_distinct_users.csv` 一致）。

## 2. 近 7 日同期（tk01 + same_hours.py）

- **定义**：把目标时段与前 7 天同一钟点的时段比较（例如今天 00:00–10:00 对比过去 7 天各自的 00:00–10:00）。
- **做法**：`python3 toolkit/same_hours.py <开始> <结束> --prev 7 > w.txt` → `shard_runner.py run --template toolkit/tk01_volume_users.sql --windows-file w.txt` → `tk_merge.py tk01`。每一行是一个窗口，直接比较同一列。
- **示例**：2026-09-24 整天 vs 09-17…09-23（逐日）：LKUS_push 请求 3,225 vs 5,576 / 5,092 / 5,391 / 3,551 / 4,738 / 5,144 / 4,691；短信去重手机号 1,845 vs 前 7 天 1,985–2,829（`results/toolkit_tests/tk01_merged.csv` 的 `requests` 与 `phones_sms` 列）。
- **门槛**：审批材料里的"相对门槛"按这里的同期对比计算；绝对量门槛（调用量 / 用户量）直接取 §1。

## 3. 命中量（tk02）

- **定义**：一条策略在窗口内的命中次数（PV）与去重手机号（UV）。`hit_list=hitStrategy` 统计在线命中，`hitPreOnlineStrategy` 统计预上线命中。
- **示例**：`strategy_MGj5bfGOijOi`（预上线）09-18…09-24 命中 13,202 次（全部 LKUS_push 行；短信口径 13,201）；09-24 当天去重手机号 466（`results/toolkit_tests/tk02_merged.csv`）。

## 4. 额外召回（tk03）

- **定义**：预上线策略命中、但最终结果是 PASS 的请求——该策略上线后**新增**处置的量。按总命中排序会误导：命中很多、却早已被在线策略拦掉的策略，上线后一条短信也省不下来。
- **做法**：tk03（只取最终 PASS 的请求）；`pv_home` 列看是否打到本国号码（误伤风险）。
- **示例**：`strategy_MGj5bfGOijOi` 7 日额外召回 4,517 次，全部是非 +1 号码（`results/toolkit_tests/tk03_merged.csv`）；全部预上线策略的额外召回见 `03` §5.2（`results/p3_strategies.csv`）。

## 5. 准确率

- **定义**：命中中被证实为黑产的比例。按提示词：对**全部命中**用 SQL 重算规则逻辑（确认命中是规则真的成立，而不是计数器异常），再加至少两类证据。
- **本包能提供的部分**：
  1. **规则复核（tk06）**：对命中集合重算计数特征，统计"命中但重算后规则不成立"的违例数。示例：`strategy_REnWrA7CfCdE` 的"区号近60分钟访问次数 > 30"，2026-09-24 命中 277 次，违例 0；引擎计数与重算相等 92.7%、±1 内 98.6%（`results/toolkit_tests/tk06_recheck_REnWr_20260924.csv`）。
  2. **证据类维度**（tk04 / E1 口径，均为聚合）：区号是否为攻击区号、手机号国家 ≠ IP 国家、token 缺失或为空、app 键缺失且自报旧版本（DR-012）、V3 低分。
- **本包拿不到的部分**：短信验证码回填（`luckyus_iupushsms.t_sent_verifycode_sms.filled` 或按日汇总表 `t_verifycode_filled_statistics`）是最直接的"真人"硬标签，但按本次约定只读了元数据（DR-007）。误伤判断需要它时，请陈晨昕提供按区号的日汇总。
- **计算**：准确率 = 命中中"规则复核通过且至少两类证据成立"的请求数 ÷ 命中数；"暂无法判断"要单列，不要算进分子或直接当误伤。

## 6. 规则复核（tk06）

- **做法**：`tk06_rule_recheck_extract.sql` 行级抽取（`--kind rows --local`，每条 ≤1 小时，只存本机）→ `recheck_counter.py --feature-id … --op … --threshold … --eval-from …`。计数定义自动读取 `results/config_counter_features.csv`（周期、维度、PV/UV、过滤条件）。
- **口径**：已用无条件特征校准（DR-003）：同一维度值、窗口 (t−period, t]、含当前请求、只计引擎评估过该特征的请求。窗口前要留出与特征周期等长的暖机时间。
- **输出**：只有条数（命中数、违例数、非命中但重算成立数、引擎与重算一致率）。

## 7. 放行泄漏与分数分布（tk04 / tk05）

- **放行泄漏**：非本国区号的 PASS，按区号、IP 国家、手机号国家 ≠ IP 国家、cid、token 状态、app 键拆分。示例：7 日 8,795 次，其中 IP 在美国 46.7%、token 缺失或为空 21.4%、V3≥0.8 占 76.9%（`03` §6）。
- **分数分布**：`tk05` + `tk_merge.py tk05 --cuts 0.3,0.8`。分段点是参数；分数越高越像真人（DR-009）。

## 8. 每日巡检（tk07）

`patrol.py --day <纽约日>` 输出一页：短信 PASS/REJECT/REVIEW、非本国区号放行占比、在线与预上线命中前 10（含其中最终 PASS 的次数）。示例：`results/toolkit_tests/tk07_patrol_20260924.md`（2026-09-24：PASS 1,718 / REJECT 1,478 / REVIEW 15；非 +1 放行 582，占 33.9%）。
