## 3. 日志分片 `t_access_log_NNNN`

- 64 张同构；单表 535–730 MB；索引 `PRIMARY(id)`、`idx_create_time_sharding_key(create_time, sharding_key)`、`idx_sharding_key_create_time(sharding_key, create_time)`。
- 1 个纽约日全场景 17,749 行，其中 LKUS_push 3,225 行（2026-09-24，`results/p1_scene_rows.csv`）。当天出现 11 个 `scene_id`（含 3 个测试租户 `IQA2_*`）。
- LKUS_push 每行平均 `response_strategy_engine` 27,304 B（`featureDetail` 11,911 B、`ruleDetail` 13,852 B）（`results/p1_payload_size.csv`）。团队手册里的 "20,641 B/行" 是 2026-09-10 的旧测量，本次未复现（引用：`out/sql-cookbook/取数SQL手册.md`，非本次查询）。
- JSON 结构（只列键）见 `dictionary/t_access_log_0000.md`。要点：
  - `$.para`（请求参数）是**被再次编码的 JSON 字符串**，要 `CAST(JSON_UNQUOTE(JSON_EXTRACT(request_strategy_engine,'$.para')) AS JSON)`；
  - `$.re.featureDetail`、`$.re.ruleDetail` 是原生数组；`$.re.hitStrategy`、`hitPreOnlineStrategy`、`hitBreakStrategy` 是**字符串里装数组**；
  - featureDetail 元素键：`featureId, name, type, code, result, comments.apiResp`；命中策略元素键：`strategyId, strategyName, strategyType, status, resultName, execPriority, vaild`。

## 5. 分片键（DR-014）

- `sharding_key = CONCAT(country_code, phone)` 在 2026-06-01、2026-08-17、2026-09-24 三个纽约日的 LKUS_push 上 100% 成立（1,382 / 1,109 / 3,225 行）（`results/p1_sk_concat_check_*.csv`）。
- 2026-08-18 约 08:00–09:00 UTC 起，请求参数新增 `fullPhoneNo`，从此 `sharding_key = fullPhoneNo`（`results/p1_sk_transition_hourly.csv`）；之前 `fullPhoneNo` 键不存在（`results/p1_chk_consistency_pre.csv`）。
- 结论：**同一手机号只落一个分片**，按分片 `COUNT(DISTINCT sharding_key)` 直接相加 = 全局去重手机号数。`uid` 不是分片键，不能相加（本次用加盐哈希在本地去重）。

## 6. 短信 vs 邮件（DR-002）

- 2026-06-01…09-24 共 116 个纽约日，LKUS_push **每一行**都有非空 `$.para.phoneNo` 和非空 `phone` 列（`results/p4_daily_series.csv`，`phone_key_nonempty=0` 与 `phone_col_nonempty=0` 均为 0 行）。
- 带 `email` 键的行每天 0–14 行（`email` 列非空与之完全同步）；7 日窗口 25 行 = 0.08%，且这些行同样带手机号，多为 iOS/Android、+1、PASS（`results/p1_dr002_email_signals.csv`）。
- 源库**没有**逐行的短信/邮件标记（没有 `l2_scene`）。可用规则：`$.para.email` 非空 → 邮件候选，其余 → 短信。本包的"短信"口径用这条规则；两种口径在 7 日窗口只差 25 行。能否用它复原数仓 `l2_scene=1002`，要林宏鹏确认（Doris 不可达，无法对照）。

## 7. 其它服务器上"名字像风控"的表（只记名字，未读数据）

| 同上 | `t_collect_verifycode` | 验证码采集表（手机号、验证码内容、采集/校验时间） |
